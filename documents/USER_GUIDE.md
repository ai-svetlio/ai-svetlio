## 🎯 Какво е AI_Svetlio?

AI_Svetlio е система от **3 слоя**:

```
┌──────────────────────────────────────────────────────────┐
│  1. CLI ИНСТРУМЕНТИ (svetlio команди в терминала)         │
│     → svetlio init, svetlio tools, svetlio repair...     │
├──────────────────────────────────────────────────────────┤
│  2. .memory/ СИСТЕМА (файлова памет на проекта)          │
│     → STATE.md, LOG.md, MODE.md, TOOLS.md...             │
├──────────────────────────────────────────────────────────┤
│  3. AI АГЕНТ ПОВЕДЕНИЕ (правила за агентите)              │
│     → Как агентът чете/пише в .memory/                   │
│     → Режими: NORMAL, REPAIR, ANALYZE...                 │
│     → Iron Rules за безопасна работа                     │
└──────────────────────────────────────────────────────────┘
```

## 📦 Инсталиране

### Предусловия

| Изискване | Минимална версия | Проверка |
|-----------|-----------------|----------|
| **Node.js** | 18.0+ | `node --version` |
| **npm** | 9.0+ | `npm --version` |

> 💡 Ако нямаш Node.js, свали го от [nodejs.org](https://nodejs.org/) — избери **LTS** версията.

### Стъпка 1: Инсталация на пакета (веднъж)
```bash
npm install -g ai-svetlio
```

**Проверка дали е инсталиран:**
```bash
svetlio --version
# Очакван резултат: 2.1.0 (или по-нова)
```

> ⚠️ Ако `svetlio` не се разпознава като команда:
> - **Windows:** Рестартирай терминала или добави npm глобалната папка в PATH
> - **macOS/Linux:** Опитай `sudo npm install -g ai-svetlio`

### Стъпка 2: Глобална настройка (веднъж)
```bash
svetlio setup
```
Това създава правила за всички поддържани IDE (Cursor, Claude Code, Antigravity).

### Стъпка 3: Инициализирай проект
```bash
# Нов проект:
mkdir my-project
cd my-project
svetlio init

# Или в съществуващ проект:
cd existing-project
svetlio onboard
```

### Стъпка 4: Отвори в IDE и работи
```bash
cursor .
# или
claude .
# или
antigravity .
```

> ✅ Готово! AI агентът автоматично ще прочете `.memory/` и ще знае контекста на проекта.

### ▶ `продължаваме` — Продължаване на работа

Копирай и залепи в чата при **всяка следваща** сесия:

| Ситуация | Шаблон |
|----------|--------|
| Първи път отваряш проект с AI | ▶ `старт` |
| Продължаваш от предишна сесия | ▶ `продължаваме` |

## ⚠️ Споделена отговорност — как работи паметта

### Важно да знаеш

Паметта на Светльо е **споделена отговорност** между теб и AI агента. AI агентът записва промените в `.memory/`, но **само ако му дадеш време да завърши**. Това е технологично ограничение, което важи за **всички AI агенти** — те нямат контрол над момента на затваряне.

### Как да приключваш сесия правилно

| Стъпка | Какво правиш |
|--------|-------------|
| 1 | Кажи на агента: "Приключваме" или "Запиши промените" |
| 2 | Изчакай агентът да потвърди записа (ще видиш обновените файлове) |
| 3 | Едва тогава затвори чата/IDE-то |

### Примери

**✅ Правилно:**
```
Ти: "Приключваме за днес, запиши какво направихме"
AI: "Готово — обнових STATE.md, LOG.md, TODO.md, PROBLEMS.md и DECISIONS.md"
→ Затваряш чата
```

**❌ Грешно:**
```
Ти: "Добре, мерси"
→ Затваряш чата веднага
→ AI не е записал нищо → паметта е неактуална
→ Следващата сесия започва с грешен контекст
```

### Какво се случва ако не изчакаш?

- `.memory/STATE.md` остава с **вчерашното** състояние
- `.memory/LOG.md` не съдържа записа на последната ти сесия
- `.memory/TODO.md` не отразява какво е направено
- `.memory/PROBLEMS.md` не отразява срещнати/решени проблеми
- `.memory/DECISIONS.md` не отразява взети решения
- Следващият AI агент (или следващата сесия) **не знае** какво е станало

> 💡 **Помни:** Това не е бъг и не може да бъде поправено — AI агентите работят само докато сесията е отворена. Твоята отговорност е да им дадеш време да запишат.

## 🗑️ Деинсталиране

### Премахване на пакета
```bash
npm uninstall -g ai-svetlio
```

### Какво остава след деинсталиране

| Компонент | Остава? | Местоположение | Действие |
|-----------|---------|---------------|----------|
| `.memory/` папка | ✅ Да | В проекта ти | Изтрий ръчно ако не ти трябва |
| `CLAUDE.md` | ✅ Да | В проекта ти | Изтрий ръчно ако не ти трябва |
| `.cursorrules` | ✅ Да | В проекта ти | Изтрий ръчно ако не ти трябва |
| `~/.ai-svetlio/` | ✅ Да | Домашна папка | Изтрий ръчно |
| `~/.claude/CLAUDE.md` | ✅ Да | Домашна папка | Изтрий ръчно |
| CLI командата `svetlio` | ❌ Не | — | Премахната автоматично |

### Пълно почистване (ако искаш да махнеш всичко)

**Windows:**
```bash
npm uninstall -g ai-svetlio
rmdir /s /q "%USERPROFILE%\.ai-svetlio"
del "%USERPROFILE%\.claude\CLAUDE.md"
del "%USERPROFILE%\.cursorrules"
```

**macOS/Linux:**
```bash
npm uninstall -g ai-svetlio
rm -rf ~/.ai-svetlio
rm ~/.claude/CLAUDE.md
rm ~/.cursorrules
```

> ⚠️ **Внимание:** `.memory/` папките в проектите ти НЕ се изтриват автоматично. Ако искаш да ги махнеш, направи го ръчно за всеки проект.

## 🔄 Безопасно обновяване

### Какво се обновява и какво НЕ

При `npm update -g ai-svetlio`:

| Компонент | Обновява се? | Обяснение |
|-----------|--------------|-----------|
| CLI инструменти | ✅ Да | Новите команди стават достъпни |
| Каталог с инструменти | ✅ Да | Виждаш новите инструменти в `svetlio tools` |
| `.memory/` папка | ❌ **НЕ** | Твоята история е в проекта, не в npm пакета |
| CLAUDE.md, .cursorrules | ❌ **НЕ** | Тези файлове са в твоя проект |

### Процедура за безопасно обновяване

#### Стъпка 1: Провери текущата версия
```bash
svetlio --version
# или
npx svetlio --version
```

#### Стъпка 2: Обнови npm пакета
```bash
npm update -g ai-svetlio
```

#### Стъпка 3: Провери новата версия
```bash
svetlio --version
```

#### Стъпка 4: Обнови правилата в съществуващ проект

**Нов в v1.5.0 — автоматично обновяване:**
```bash
cd my-project
svetlio upgrade
```

Командата `svetlio upgrade`:
- ✅ Прави backup на старите правила в .memory/backups/
- ✅ Генерира нови CLAUDE.md, .cursorrules, .antigravity/rules.md
- ✅ Показва diff — какво е добавено/променено
- ❌ **НЕ пипа** .memory/ (паметта е безопасна)
- ❌ **НЕ пипа** .requests/ (заявките са безопасни)

> 💡 Това е **препоръчителният** начин за обновяване на правилата. Алтернативно можеш да ползваш `svetlio init`, но ще трябва ръчно да внимаваш за .memory/.

### 🧠 Как да запазиш паметта при обновяване

Когато `svetlio init` попита "Искаш ли да презапишеш?":

```
⚠️  Проектът вече има .memory/ папка.
? Искаш ли да презапишеш? (y/N)
```

**Отговори `N` (Не)** ако искаш да запазиш историята си (LOG.md, STATE.md, DECISIONS.md и т.н.)

#### Какво можеш да презапишеш безопасно:

| Файл | Презаписвай? | Защо |
|------|-------------|------|
| **CLAUDE.md** | ✅ Да | Получаваш новите Iron Rules и подобрения |
| **.cursorrules** | ✅ Да | Получаваш новите правила за Cursor |
| **.antigravity/rules.md** | ✅ Да | Получаваш новите правила за Antigravity |
| **.memory/** | ❌ **НИКОГА** | Тук е цялата история на проекта |

#### Вариант 1: Безопасно обновяване (запази паметта)
```bash
cd my-project
svetlio init
# ? Искаш ли да презапишеш? → N (Не)
```
След това ръчно копирай само правилата:
```bash
# Виж какво е новото в CLAUDE.md шаблона:
npx svetlio init --name temp-project   # в празна папка
# Сравни и ръчно прехвърли каквото искаш
```

#### Вариант 2: Пълно обновяване (нов проект без история)
```bash
cd my-project
svetlio init
# ? Искаш ли да презапишеш? → Y (Да)
# ⚠️ Внимание: Ще загубиш LOG.md, STATE.md и цялата история!
```

#### Вариант 3: Обновяване с backup (препоръчително)
```bash
cd my-project

# 1. Backup на паметта
cp -r .memory/ .memory-backup/

# 2. Обнови всичко
svetlio init
# ? Искаш ли да презапишеш? → Y (Да)

# 3. Върни паметта
cp -r .memory-backup/* .memory/

# 4. Изтрий backup
rm -rf .memory-backup/
```

> 💡 **Препоръка:** Използвай **Вариант 3** — така получаваш новите правила и запазваш цялата история.

### Какво е безопасно

| Действие | Безопасно? | Защо |
|----------|------------|------|
| `npm update -g ai-svetlio` | ✅ Винаги | Не пипа проектите ти |
| `svetlio init` в нов проект | ✅ Винаги | Няма какво да се загуби |
| `svetlio init` + каже **Не** за презапис | ✅ Безопасно | Нищо не се променя |
| `svetlio init` + каже **Да** без backup | ⚠️ Опасно | Губиш .memory/ историята |
| `svetlio init` + backup + презапис + възстанови | ✅ Безопасно | Най-добрият вариант |

### Пример: Обновяване от v1.0.0 на v1.2.0

```bash
# 1. Виж какво имаш
svetlio --version
# Резултат: 1.0.0

# 2. Обнови
npm update -g ai-svetlio

# 3. Потвърди
svetlio --version
# Резултат: 1.2.0

# 4. В съществуващ проект - обнови правилата
cd my-project
svetlio init
# Избери: Да за CLAUDE.md, Не за .memory/

# 5. Провери новите функции
svetlio tools
svetlio registry database
```

## 🔧 Режими на работа

### NORMAL (по подразбиране)
- Стандартна работа
- AI обновява .memory/ след промени
- Бързо, fluid развитие

### REPAIR (за поправки)
**Активация:** `svetlio repair` или кажи "режим ремонт"

- Backup преди ВСЯКА промяна
- Одобрение преди ВСЯКА стъпка
- Детайлно обяснение какво и защо

### ONBOARD (за съществуващ проект)
**Активация:** `svetlio onboard`

- Сканира целия проект
- Извлича логика и структура
- Създава .memory/ автоматично

### ANALYZE (за legacy системи)
**Активация:** `svetlio analyze`

- Дълбок анализ на всичко
- Документира бизнес логика
- Предлага EXTEND или REWRITE

```
.memory/

├── analysis/         ← От ANALYZE режим
├── rewrite/          ← За REWRITE режим
└── backups/          ← Backups от REPAIR режим
```

## 🔒 Iron Rules (Железните правила)

AI агентите следват тези правила за безопасна работа:

### Памет и контекст
1. **ПАМЕТ ПЪРВО** — Винаги започва от .memory/
2. **НЕ ГАДАЙ** — Чете документация, не търси "на посоки"
3. **ПРОЧЕТИ ЦЕЛИЯ КОД** — Не редактира "на парче"
4. **CONTEXT REFRESH** — Освежава контекста на всеки ~15 съобщения

### Безопасност
5. **ЗАДЪЛЖИТЕЛЕН BACKUP** — Преди редакция на работещ код
6. **ЗАЩИТЕНИ ЗОНИ** — Не пипа критични папки без одобрение
7. **ВЕРИФИЦИРАЙ** — Проверява резултата, не приема "на сляпо"

### Процес
8. **ДОКУМЕНТИРАЙ ПЪРВО** — Записва решение преди код
9. **СТРУКТУРА** — Всичко на правилното място
10. **ГОЛЕМИ ЗАДАЧИ = МАЛКИ СТЪПКИ** — Разбива сложното на части
11. **ПИТАЙ ПРИ СЪМНЕНИЕ** — По-добре да пита, отколкото да чупи

**Пълна документация:** [IRON_RULES.md](./IRON_RULES.md)

## 📋 ClientRequests система (v1.5.0+)

При `svetlio init` се създава `.requests/` папка за управление на клиентски заявки.

### Структура
```
.requests/
├── inbox/       ← Сложи файлове тук за обработка
├── processed/   ← Структурирани заявки (CR-YYYY-NNN.md)
├── archive/     ← Завършени заявки
└── python/      ← Python инструменти
```

### CLI команди
```bash
svetlio requests          # Списък на заявки (от REGISTRY.md)
svetlio requests check    # Провери inbox за нови файлове
svetlio requests process  # Обработи файлове от inbox (Python bridge)
svetlio requests archive  # Покажи завършени заявки за архивиране
```

### Поддържани формати
- **Винаги работят:** TXT, MD
- **С Python:** EML, MSG, DOCX, XLSX, PDF, RTF

> 💡 Инсталирай Python зависимостите за пълна поддръжка: `pip install -r .requests/python/requirements.txt`

## ❓ Често задавани въпроси

### Q: Каква е разликата между `svetlio tools` и `.memory/TOOLS.md`?
**A:**
- `svetlio tools` → показва **каталога** с налични инструменти (какво можеш да ползваш)
- `.memory/TOOLS.md` → показва **избраните** инструменти за този проект

### Q: Кога да използвам REPAIR режим?
**A:** Когато:
- Нещо е счупено и искаш внимателна поправка
- Работиш с критичен код
- Искаш backup преди всяка промяна
- Просто искаш повече контрол

### Q: Какво е Context Refresh?
**A:** След дълъг чат (~15 съобщения), AI агентът "освежава" паметта си като прочита .memory/ файловете отново. Това предотвратява грешки от "забравяне".

### Q: Как да кажа на агента да внимава повече?
**A:** Кажи:
- "внимавай"
- "важно е"
- "режим ремонт"
- "backup първо"

### Q: Как да обновя AI_Svetlio без да загубя работата си?
**A:**
1. `npm update -g ai-svetlio` е **винаги безопасно** — не пипа проектите ти
2. `.memory/` папката е в твоя проект, не в npm пакета
3. Ако искаш новите правила (Iron Rules), изпълни `svetlio init` в проекта
4. При `svetlio init` **не презаписвай .memory/** ако имаш история

### Q: Ще загубя ли LOG.md и STATE.md при обновяване?
**A:** **НЕ.** Тези файлове са в `.memory/` папката на твоя проект. npm пакетът съдържа само CLI инструментите. Твоята история е изцяло в проекта и никога не се пипа при `npm update`.
